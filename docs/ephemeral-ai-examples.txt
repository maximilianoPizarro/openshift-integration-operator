================================================================================
  Ephemeral AI examples — complete properties in the IntegrationFlow CR
================================================================================

These flows run in EPHEMERAL mode (no Git). Each example uses plain-text prompts
in kaotoDesign and expects you to fill credentials in spec.ephemeral.properties
and/or a Kubernetes Secret before the worker can call an LLM.

Prerequisites (once per namespace)
----------------------------------
  oc create secret generic openai-credentials -n openshift-integration \
    --from-literal=OPENAI_API_KEY=sk-proj-REPLACE_ME

Optional overrides in the Secret (instead of properties):
  OPENAI_MODEL=gpt-4o-mini
  OPENAI_EMBEDDING_MODEL=text-embedding-3-small

Apply any example:
  oc apply -f k8s/examples/ephemeral-ai/01-openai-simple-chat.yaml
  oc get integrationflow -n openshift-integration -w
  oc logs deploy/iflow-ephemeral-ai-simple-chat-worker -n openshift-integration -f

How CR properties reach the LLM (must all be true)
--------------------------------------------------
  1. spec.ephemeral.properties uses Quarkus keys (quarkus.langchain4j.openai.*)
  2. Operator merges them into ConfigMap application.properties (EphemeralConfigMerger)
  3. Worker pod sets QUARKUS_CONFIG_LOCATIONS=file:/deployments/config/application.properties
  4. camel-worker-ai includes quarkus-langchain4j-openai (ChatModel CDI bean)
  5. Routes use langchain4j-chat without chatModel=#bean — default model from properties

Change model per flow — edit only the CR:
  spec:
    ephemeral:
      properties:
        quarkus.langchain4j.openai.chat-model.model-name: "gpt-4o"
        quarkus.langchain4j.openai.chat-model.temperature: "0.2"

Ollama (OpenAI-compatible base-url):
  spec:
    ephemeral:
      properties:
        quarkus.langchain4j.openai.base-url: "http://ollama.host:11434/v1"
        quarkus.langchain4j.openai.api-key: "ollama"
        quarkus.langchain4j.openai.chat-model.model-name: "llama3.2"

Worker image: auto-selects camel-worker-ai when langchain4j-chat is detected.
Force AI tier: spec.ephemeral.workerImage: quay.io/.../camel-worker-ai:v0.5.0

Property cheat sheet (spec.ephemeral.properties)
--------------------------------------------------
  REQUIRED (OpenAI-compatible)
    quarkus.langchain4j.openai.api-key=${OPENAI_API_KEY}
    quarkus.langchain4j.openai.chat-model.model-name=gpt-4o-mini

  OPTIONAL tuning
    quarkus.langchain4j.openai.chat-model.temperature=0.7
    quarkus.langchain4j.openai.chat-model.max-completion-tokens=1024
    quarkus.langchain4j.openai.chat-model.log-requests=true
    quarkus.langchain4j.openai.chat-model.log-responses=true

  Ollama / local OpenAI-compatible API (replace OpenAI block)
    quarkus.langchain4j.openai.base-url=http://HOST:11434/v1
    quarkus.langchain4j.openai.api-key=ollama
    quarkus.langchain4j.openai.chat-model.model-name=llama3.2

  Azure OpenAI (example — adjust endpoint and deployment names)
    quarkus.langchain4j.openai.base-url=https://YOUR_RESOURCE.openai.azure.com/openai/deployments/YOUR_DEPLOYMENT
    quarkus.langchain4j.openai.api-key=${AZURE_OPENAI_API_KEY}
    quarkus.langchain4j.openai.chat-model.model-name=gpt-4o

Secret wiring (spec.secrets)
----------------------------
  secrets:
    - name: openai-credentials
      envFrom: true
